# F11 · F0.2 Mobile Data Layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native screens load server data the same way the web does (TanStack Query over the authenticated session), checkout recovery works on mobile, and query keys have one shared definition.

**Architecture:** A synchronous `KeyValueStore` interface in shared (the shape `CheckoutCoordinator` already uses: `getItem/setItem/removeItem`); web passes `localStorage`, mobile passes an adapter over `expo-secure-store`'s sync API. `CheckoutCoordinator` moves to shared; web keeps only its `window.localStorage` factory. Query keys get one factory module in shared that reproduces today's web keys exactly. Mobile gets one `QueryClient`, cleared on every session clear, refetching on app foreground, plus `useAuthedQuery` / `useAuthedMutation`; the native Tickets list is converted as the first real user.

**Tech Stack:** `@tanstack/react-query` ^5 (same major as web), `expo-secure-store` 58 (sync `getItem`/`setItem`), React Native `AppState`, vitest.

**Spec:** `docs/superpowers/plans/2026-11-26-mobile-native-rebuild.md` § Phase 0 → F0.2.

## Global Constraints
- Branch `feat/f11-f0-2-data-layer-slyamshaikhov` from `master` 17e78ce or later. No Claude attribution anywhere.
- No web behaviour change; `npm run check` green after every task; `npm run export:mobile` green at the end.
- Guard from F0.1 stays green: nothing in `shared/src` touches browser/React APIs (so the shared store takes the storage as a parameter, never reads `window`).
- Persist only opaque identifiers (same rule as web `attempt.ts`): no attendee names, emails or order bodies in SecureStore.
- Web call sites of query keys are **not** migrated in this step (avoids another round of conflicts with open web branches); the shared factory must return arrays deep-equal to today's web literals so the migration later is a no-op.
- Mobile-only deps installed with `npx expo install` from `frontend/mobile`.

## Review Focus
- Sign-out or session expiry on mobile → the query cache is empty before the next account's first render (no previous user's tickets flash on screen).
- SecureStore key rules (only `A-Z a-z 0-9 . - _`) vs checkout keys like `biletflow:f3:attempt:<user>:<event>` → adapter must encode, collision-free.
- SecureStore has no sync delete → `removeItem` must make an immediate `getItem` return "missing", not the old value.
- App returns from background → visible queries refetch (tickets status updated after a refund elsewhere).
- Mobile offline while a query runs → error state with retry from the existing screens, no unhandled promise rejection.
