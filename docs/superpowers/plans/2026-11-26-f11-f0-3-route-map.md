# F11 · F0.3 Route Map and Web → Native Handoff — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any web page that already has a native screen opens natively — from a link inside the BiletFlow web tab or from a deep link — so each future work package only adds one line to a route map.

**Architecture:** Approach A (chosen by the user): keep the single BiletFlow web tab; native tabs appear as their screens land. One route map (`mobile/src/navigation/routes.ts`) lists web path patterns that have native screens. The web tab intercepts both full page loads (`onShouldStartLoadWithRequest`) and in-page React Router navigations (an injected script that wraps `history.pushState` / `replaceState` and posts the path to the app instead of navigating when it matches a native pattern). React Navigation `linking` is generated from the same map for deep links.

**Tech Stack:** react-native-webview 14 (`injectedJavaScriptBeforeContentLoaded`, `onMessage`), React Navigation 7 `linking`, `expo-linking` (`createURL`, Expo Go `exp://…/--/` prefix), vitest + `node:vm` for the injected script.

**Spec:** `docs/superpowers/plans/2026-11-26-mobile-native-rebuild.md` § F0.3, amended by the user's choice of approach A (no extra web-backed tabs: each embedded web view has its own private sign-in).

## Global Constraints
- Branch `feat/f11-f0-3-route-map-slyamshaikhov` from `master` cd58d1c or later. No Claude attribution anywhere.
- No web app changes. `npm run check` green after every task; `npm run export:mobile` green at the end.
- Only same-origin paths are matched; the route map never sees other hosts (those still open in the system browser).
- Initial native routes (the screens that exist today): `/account/tickets` → Tickets tab; `/account/tickets/:ticketId` → `TicketDetail`. `/tickets` (email link alias) is **not** mapped: on web it resolves the session first, so it stays web.
- Every pattern in the map must exist in `web/src/App.tsx` (test-enforced), so a typo cannot silently never match.
- Custom URL schemes / https universal links need a native build; in Expo Go deep links arrive as `exp://<host>/--/<path>`. Register `scheme: "biletflow"` in `app.json` for later builds, but test only `createURL` prefixes.

## Review Focus
- Tap "My tickets" in the web tab's account menu (client-side navigation, no page load) → native Tickets tab opens; the web tab stays on the page it was on (not on a blank or half-navigated state).
- Browser back/forward inside the web tab (popstate) → never triggers the native handoff (only forward navigations do).
- Query string or hash on a mapped path (`/account/tickets?x=1#y`), trailing slash, percent-encoded id → still matched, id decoded once.
- A path that only starts like a mapped one (`/account/tickets-archive`, `/account/tickets/1/extra`) → not matched, stays web.
- Signed-out user taps a mapped link → native screen shows its signed-out state (sign-in panel), no crash.

### Task 1: Route map

**Files:** Create `frontend/mobile/src/navigation/routes.ts`, `frontend/mobile/src/navigation/routes.test.ts`

**Interfaces — Produces:**
- `type NativeTarget = { screen: "Tickets" } | { screen: "TicketDetail"; params: { ticketId: string } }`
- `const nativeRoutes: readonly { pattern: string; to: (params: Record<string, string>) => NativeTarget }[]` — entries: `"/account/tickets"` → `{ screen: "Tickets" }`, `"/account/tickets/:ticketId"` → `{ screen: "TicketDetail", params: { ticketId } }`
- `matchPath(pattern: string, path: string): Record<string, string> | null` — exact segment match, `:name` captures one segment, decodes `decodeURIComponent` once; ignores query/hash and one trailing slash.
- `nativeRouteFor(url: string, origin: string): NativeTarget | null` — accepts absolute same-origin URLs or root-relative paths; other origins → null.

### Task 2: Injected navigation guard

**Files:** Create `frontend/mobile/src/navigation/guard.ts`, `frontend/mobile/src/navigation/guard.test.ts`

**Interfaces — Produces:**
- `nativePatternSources(): string[]` — one anchored RegExp source per `nativeRoutes` pattern (`:x` → `[^/]+`, optional trailing slash, optional `?…`/`#…`).
- `guardScript(sources: string[]): string` — self-contained JS (no imports, ES2017) that wraps `history.pushState` and `history.replaceState`: resolve the target URL against `location.href`; if same origin and its pathname matches a source, call `window.ReactNativeWebView.postMessage(JSON.stringify({ type: "native-route", path: pathname + search + hash }))` and **do not** call the original; otherwise call the original. It never touches `popstate`. Ends with `true;`.
- `parseGuardMessage(data: string): { path: string } | null` — accepts only `{type:"native-route", path: string starting with "/"}`.

- [ ] Step 1: tests run `guardScript(nativePatternSources())` in `vm.runInNewContext` with a fake `{ location: { href, origin }, history: { pushState: spy, replaceState: spy }, window: { ReactNativeWebView: { postMessage: spy } }, URL }`:
  - `history.pushState({}, "", "/account/tickets")` → postMessage called with that path, original pushState **not** called.
  - `pushState({}, "", "/events/1")` → original called, no message.
  - `pushState({}, "", "https://other.example/account/tickets")` → original called.
  - `replaceState` behaves the same as pushState.
  - `parseGuardMessage` rejects non-JSON, wrong type, `path` without leading `/`.
- [ ] Step 2: run → FAIL. Step 3: implement. Step 4: → PASS; `npm run check` green.
- [ ] Step 5: commit `feat(f11): injected guard hands mapped web navigations to the app`.
